# UnDiffused Benchmark Protocol

## Purpose

This document defines the reproducible evaluation methodology for UnDiffused V2 and V3.
All release gates must be validated against this protocol before shipping.

## Primary Metrics

| Metric | Definition | Target (V2) |
|--------|-----------|-------------|
| AUROC | Area under ROC curve over the full test set | > 0.90 |
| F1 @ threshold | F1 score at the decision threshold from `fusion_v2.json` | > 0.85 |
| FPR@95TPR | False positive rate when TPR is fixed at 95% | < 0.15 |
| ECE | Expected Calibration Error (10 bins) | < 0.05 |

> "95% accuracy" is not a metric target — AUROC and F1 at a defined benchmark partition are.

## Latency Metrics

Measured on a reference machine: MacBook M2 (8-core CPU) with Chrome 124.
- Normal scan p50 ≤ 6s, p90 ≤ 8s
- Deep scan (1080p image) p50 ≤ 30s, p90 ≤ 40s
- Cold-start model load ≤ 4s

## Memory Metrics

Measured with Chrome Task Manager during deep scan:
- Peak RAM < 1.5 GB
- Steady-state after scan (both models loaded) < 500 MB

## Benchmark Partitions

### In-Domain (primary)
Used for release gating. Contains images matching the deployment distribution.

| Split | Real sources | AI sources |
|-------|-------------|------------|
| Train | Unsplash, COCO, Flickr-CC | DALL-E 3, Midjourney v6, SD XL |
| Val   | 10% holdout from same sources | 10% holdout |
| Test  | Separate download with no overlap | Separate download |

### Out-of-Domain (generalization check)
Used for robustness reporting but NOT for release gating alone.

| Transform | Description |
|-----------|-------------|
| JPEG sweep | Recompressed at Q=30, Q=60, Q=85 |
| Resize chain | Resize to 512px then back to original |
| Screenshot | PNG screenshot of browser rendering |
| Unseen generators | Adobe Firefly, Imagen 3, Flux |

### Split hygiene rules
1. No image appears in more than one split.
2. Near-duplicate removal via perceptual hash (phash distance > 8) across all splits.
3. Generator family holdout: at least one AI generator family withheld from training entirely.

## Evaluation Commands

```bash
# Run full benchmark after training
python scripts/eval.py \
  --global_onnx  public/models/model_global_quantized.onnx \
  --global_meta  public/models/model_global_meta.json \
  --local_onnx   public/models/model_local_quantized.onnx \
  --local_meta   public/models/model_local_meta.json \
  --fusion_cfg   public/models/fusion_v2.json \
  --data_dir     /path/to/test_set \
  --output       benchmarks/v2_candidate.json
```

## Report Archiving

Each release must include a `benchmarks/v2_candidate_<date>.json` file committed to the repo.
The file is generated by `scripts/eval.py` and includes all metrics defined above.

Comparison with the previous release benchmark is required before merging to main.
